# 技術決策

| 決策 | 原因與代價 |
|---|---|
| 採實體翻牌與固定格位 | 現場以桌面遊戲為主。固定格位讓未揭曉的牌也可記錄指尖位置。移動相機或改變牌位要重新校正。 |
| 白背保持素面，正面以兩個 AprilTag 識別 | 白背朝上時維持牌面未知。兩個前置標記改善幾何擬合，也能在單標記可見時降級。早期的背面 Tag 方案因需求排除。 |
| 使用 AprilTag 36h11 與既有印刷對照 | 已有 16 個可辨識標記，位置也用原版卡片建立參考。16h5 和更大的印刷標記列為對照實驗，程式目前未切換牌組、字典或預設偵測參數。 |
| 開局自動偵測白背，手動校正備援 | 常規桌面可少做標註。遇到背景亮或排法不清楚時可人工指定。格位配置在本局保持固定。 |
| 無法確認時保留狀態 | Tag 消失可能是遮擋或漏讀。等白背或正面成立並持續三幀，再記錄事件。 |
| MediaPipe 負責關鍵點，OpenCV 負責幾何 | 各自有清楚的輸入輸出。現階段用二維指尖與牌框/格位配對，沒有相機外參、3D 落點或接觸判定。 |
| CSV 作為後續分析介面 | 影格資料、翻牌與合併時間軸可各自核對。之後語音及分析可離線讀寫，避免干擾即時取圖。 |
| 遊戲面板以 OpenCV 和 Pillow 呈現 | 沿用同一預覽視窗，按 D 可回到原始事件畫面。回合介面狀態目前不持久化。 |
| 相機採單格佇列和等待逾時 | 減少影像堆積並讓 GUI 能處理離開按鍵。代價是可能丟掉短暫翻牌影格。影片模式順序讀取用於回歸。 |

提案曾考慮平板遊戲，後續確認採實體牌。聲音、頭部方向、記憶策略或提示的整合尚在 [待辦](TODO.md)。
